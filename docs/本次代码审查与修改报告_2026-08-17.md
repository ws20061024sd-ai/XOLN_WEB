## 二、审查发现的问题清单

### P0：管理接口鉴权完全失效

| 位置 | 问题 |
|---|---|
| `server/src/routes/admin.ts` | 子应用内鉴权中间件写成 `admin.use("/api/admin/*")` |
| `server/src/index.ts` | 子应用挂载为 `app.route("/api/admin", admin)` |
| 结果 | Hono 会把子应用路径再拼一次，中间件实际注册为 `/api/admin/api/admin/*`，永远匹配不到真实请求 |
| 影响 | 任何人无需密钥即可读取联系表单消息、删除评论/留言/共创投稿、修改审核状态 |
| `server/src/routes/admin.ts` | `ADMIN_KEY = process.env.ADMIN_KEY \|\| "admin123"` |
| `docker-compose.yml` | 未注入 `ADMIN_KEY` |
| `docs/开发审查清单.md` | 明文写着默认密钥 `admin123` |

### P1：高风险问题

1. 评论/留言默认 `approved=1`，提交后直接公开（**用户决定本次不修改**）。
2. 限流 Map 永不过期，会随 IP 数量无限增长；IP 取值信任 `x-real-ip` / `x-forwarded-for`。
3. `sql.js` 每次写操作都全量导出数据库并同步写文件，无原子写保护，进程中途崩溃可能损坏 `blog.db`。
4. `getDb()` 没有缓存初始化 Promise，并发首次请求可能创建多个数据库实例。
5. `Dockerfile` 只 `COPY package.json` + `COPY dist/`，不编译源码，依赖人工 scp dist；`npm install` 不可复现。
6. `docker-compose.yml` 端口 `3001:3001` 直接暴露公网。
7. `upload.js` 部分文件上传失败后仍写入完整 manifest，下一次运行会误认为失败文件已上传。
8. `/works/quant` 页面 iframe 指向 `/works/quant/index.html`，但仓库和 Next.js 构建产物中都不存在该文件。

### P2：中等问题

1. API 地址三套逻辑不一致：`lib/api.ts`、`AdminPanel.tsx`、`GuestbookClient.tsx` 各自处理。
2. 评论/联系/留言/投稿提交函数网络异常时没有 `finally`，按钮会永久停在“提交中”。
3. `fetchCommunityPost()` 不检查 404，无效 id 会渲染成一篇“假文章”。
4. 作品评论 slug 只用文件名，不同目录同名文章会共享评论。
5. 后端缺少字段类型、长度、邮箱格式校验。

### P3：小问题 / 文档偏差

- 文档与技术栈不一致（better-sqlite3 vs sql.js、默认审核策略、限流参数、Dockerfile）。
- README 仍是 create-next-app 模板。
- 管理列表无分页、搜索页把全站正文打进客户端。
- 量化仪表盘数据陈旧（本地 output 为 2026-07-10 快照）。

## 三、本次实际修改明细

### 3.1 后端安全修改

#### `site/server/src/routes/admin.ts`

修改前：

```ts
const ADMIN_KEY = process.env.ADMIN_KEY || "admin123";

const admin = new Hono();

admin.use("/api/admin/*", async (c, next) => {
  const key = c.req.header("x-admin-key");
  if (key !== ADMIN_KEY) {
    return c.json({ error: "未授权" }, 401);
  }
  await next();
});
```

修改后：

```ts
const ADMIN_KEY = process.env.ADMIN_KEY;

if (
  !ADMIN_KEY ||
  ADMIN_KEY.length < 12 ||
  ADMIN_KEY === "please_change_me_to_a_long_random_value"
) {
  console.error(
    "[admin] ADMIN_KEY 未设置、长度不足 12 位或仍为示例值，拒绝启动。\n" +
    "请通过环境变量 ADMIN_KEY 配置强密钥，例如：openssl rand -hex 24"
  );
  process.exit(1);
}

const admin = new Hono();

// admin 子应用挂载在 /api/admin 下，因此这里必须是 /* 而不是 /api/admin/*
admin.use("/*", async (c, next) => {
  const key = c.req.header("x-admin-key");
  if (key !== ADMIN_KEY) {
    return c.json({ error: "未授权" }, 401);
  }
  await next();
});
```

关键点：

- 路径 `/*` 挂载到 `/api/admin` 后成为 `/api/admin/*`，真正覆盖所有 admin 接口。
- 无 `ADMIN_KEY`、长度不足 12、或仍为 `.env.example` 示例值时，服务直接拒绝启动。
- 密钥不再有默认值。

#### `site/server/src/load-env.ts`（新增）

```ts
import { existsSync } from "node:fs";
import path from "node:path";
import { fileURLToPath } from "node:url";

const __dirname = path.dirname(fileURLToPath(import.meta.url));
const envPath = path.join(__dirname, "..", ".env");
const loadEnvFile = (process as unknown as { loadEnvFile?: (file: string) => void })
  .loadEnvFile;

if (existsSync(envPath) && typeof loadEnvFile === "function") {
  try {
    loadEnvFile(envPath);
  } catch (err) {
    console.warn(`[env] 读取 ${envPath} 失败:`, err);
  }
}
```

作用：本地 `npm run dev` 时自动读取 `server/.env`，不用手动 export 环境变量。

#### `site/server/src/index.ts`

- 第一行新增 `import "./load-env.js";`，保证 `admin.ts` 被加载前 `.env` 已经注入。
- 限流中间件修改：
  - `X-Forwarded-For` 只取逗号分隔后的第一个值。
  - 所有 IP 字符串做 `trim()`。
  - 当 `rateLimit.size > 10000` 时清理过期条目，避免 Map 无限增长。

#### `site/server/src/db/schema.ts`

- `db` 类型改为 `Database | undefined`。
- 新增 `dbPromise`，`getDb()` 复用同一个初始化 Promise，避免并发首次请求创建多个数据库实例。
- `saveDb()` 修改为：

```ts
const tmpPath = `${dbPath}.tmp`;
fs.writeFileSync(tmpPath, Buffer.from(data));
fs.renameSync(tmpPath, dbPath);
```

先写临时文件再 rename，避免进程在写文件中途崩溃导致数据库损坏。

### 3.2 Docker 部署修改

#### `site/server/Dockerfile`

修改前：

```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY package.json .
RUN npm install --registry=https://registry.npmmirror.com
COPY dist/ dist/
EXPOSE 3001
CMD ["node", "dist/index.js"]
```

修改后：

```dockerfile
FROM node:22-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci --registry=https://registry.npmmirror.com
COPY tsconfig.json ./
COPY src/ src/
RUN npm run build

FROM node:22-alpine AS runtime
WORKDIR /app
ENV NODE_ENV=production
COPY package*.json ./
RUN npm ci --omit=dev --registry=https://registry.npmmirror.com
COPY --from=build /app/dist ./dist
EXPOSE 3001
CMD ["node", "dist/index.js"]
```

意义：

- 服务器只需要收到 `server/` 源码，不再依赖本地编译好的 dist。
- 构建可复现：使用 `npm ci` + `package-lock.json`。
- 运行阶段只安装生产依赖。

#### `site/server/docker-compose.yml`

```yaml
services:
  api:
    build: .
    ports:
      - "127.0.0.1:3001:3001"
    volumes:
      - ./data:/app/data
    restart: always
    environment:
      - PORT=3001
      - NODE_ENV=production
      - ADMIN_KEY=${ADMIN_KEY:?请在 server/.env 中设置 ADMIN_KEY}
```

关键点：

- 端口只绑定服务器本机，外网必须走 Nginx。
- `ADMIN_KEY` 未配置时 compose 直接报错退出。

### 3.4 上传脚本修改

#### `site/upload.js`

修改点：

1. `uploadFile()` 失败自动重试 3 次，间隔 300ms / 600ms。
2. `uploadManifest()` 上传失败会 reject，不再吞错误。
3. 新增 `uploadedKeys` / `failedKeys` 集合。
4. 部分失败时生成的 manifest 规则：
   - 上传成功的文件 → 写新 hash
   - 上传失败的文件 → 保留旧 manifest hash（如果存在）
   - 新文件上传失败 → 不写入 manifest
   - 下次运行会重新对比并自动重试失败文件
5. 只有全部成功才认为本轮完全成功；有失败时 `process.exitCode = 1` 并打印失败列表。
6. 无文件上传但删除了旧文件时，会同步更新 manifest。
