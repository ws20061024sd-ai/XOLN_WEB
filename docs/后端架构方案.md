# 后端架构方案

> **状态**：Phase 2 持续迭代（2026-08-17）。API 上线、评论/留言板/共创/管理面板全部就绪，22 个接口含 health。
> 前端 `localhost:3099`，后端 `api.xolnxoln.cn`，管理面板 `/admin`，共创 `/community`。

## 整体架构

```
用户浏览器
    │
    ├── yourdomain.com        → 腾讯云 COS（静态前端，已就绪）
    │   获取 HTML/CSS/JS
    │
    └── api.yourdomain.com    → 腾讯云 Lighthouse（动态 API，Phase 2）
        评论 / 统计 / 表单 / ...
```

前端和后端是两个独立的东西，互不绑定：
- 前端在 COS 上，纯静态，永远在线
- 后端在 Lighthouse 上，跑 API 服务
- 前端通过 `fetch` 调用后端，后端挂了不影响页面展示

## Lighthouse 是什么

腾讯云轻量应用服务器。本质上是一台 24 小时开机的云电脑，装了 Linux。

| 对比 | COS（你已在用） | Lighthouse（Phase 2 购买） |
|------|---------------|--------------------------|
| 本质 | 网盘，存文件 | 虚拟机，跑程序 |
| 能干嘛 | 存放 HTML/CSS/JS，浏览器直接访问 | 运行 Node.js、数据库、Nginx |
| 有系统吗 | 无 | Linux |
| 计费 | 按存储和流量，几乎免费 | 按月付固定费用 |
| 月费 | ≈ 0 元 | ≈ 40 元起 |

**推荐配置**：入门型 2核1G，40GB SSD，约 40 元/月。个人博客的 API 完全够用。

## 技术栈

| 组件 | 选择 | 理由 |
|------|------|------|
| API 框架 | Hono | 12KB，路由即类型，内置 CORS |
| 数据库 | SQLite（sql.js） | 纯 JavaScript，跨平台部署无需编译，单文件存储 |
| 部署 | Docker + Nginx | 多阶段构建，自动重启，Nginx 反代 |
| 认证 | 管理员密钥 | 管理接口用 `x-admin-key` 请求头校验 |
| 评论认证 | 无需登录 | 访客直接提交，留言/评论当前默认公开 |

### 为什么 SQLite（sql.js）而不是 MySQL

- SQLite 不需要安装数据库服务，一个 `blog.db` 文件就是整个数据库
- 个人博客体量下性能完全过剩（每秒能处理几万次查询）
- 备份 = 复制文件。迁移 = 复制文件
- Lighthouse 上不需要额外内存跑数据库进程
- `sql.js` 是纯 JavaScript 实现，不依赖原生编译，Docker 内跨平台部署不会出现 `Exec format error`

需要注意：`sql.js` 是内存数据库，每次写操作后需要把整个库导出写回磁盘。当前数据量小完全可用；未来 PV/评论规模变大后，建议切换到 better-sqlite3 或 Turso。

## API 设计

### 评论系统

```
GET    /api/comments/:slug          获取某篇文章的评论列表
POST   /api/comments                提交新评论（需校验）
PATCH  /api/comments/:id/approve    审核通过（管理接口，需密钥）
DELETE /api/comments/:id            删除评论（管理接口，需密钥）
```

**数据库表**：

```sql
CREATE TABLE comments (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  slug        TEXT NOT NULL,          -- 文章标识（如 "worldview"）
  section     TEXT NOT NULL,          -- 栏目（如 "beliefs"）
  author      TEXT NOT NULL,          -- 评论者昵称
  content     TEXT NOT NULL,          -- 评论内容
  approved    INTEGER DEFAULT 1,      -- 0=待审核, 1=已通过（当前评论默认直接公开）
  created_at  DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

**当前反垃圾策略**：
- 提交时校验字段长度（昵称 ≤50字，内容 ≤5000字，slug ≤200字）
- 全局限流：每个 IP 每秒最多 5 次请求
- 评论和留言当前默认公开（`approved=1`）；共创投稿默认待审核（`approved=0`）
- 管理端可以随时隐藏或删除评论/留言

### 阅读统计

```
POST /api/stats/pageview     记录一次页面访问（前端每个页面加载时调用）
GET  /api/stats/top          获取访问量最高的文章 Top 10
GET  /api/stats/summary      获取总 PV/UV 概览
```

```sql
CREATE TABLE pageviews (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  path      TEXT NOT NULL,       -- 页面路径
  ip        TEXT,                -- 去重用
  user_agent TEXT,               -- 浏览器信息
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

前端每个页面加载时发一个 POST 请求。不需要用户交互，无感知。

### 联系表单

```
POST /api/contact   提交联系表单
```

```sql
CREATE TABLE messages (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  name      TEXT NOT NULL,
  email     TEXT NOT NULL,
  content   TEXT NOT NULL,
  read      INTEGER DEFAULT 0,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

提交后存储到数据库，同时发一封邮件通知你（用 Nodemailer + QQ 邮箱/Gmail SMTP）。

## 前端如何调用后端

前端通过统一的 API 工具函数调用后端。所有组件统一从 `src/lib/api.ts` 取 `API_BASE`，不要各自硬编码：

```ts
// site/src/lib/api.ts
export const API_BASE =
  process.env.NEXT_PUBLIC_API_URL || "https://api.xolnxoln.cn";

export async function postComment(data: { slug: string; author: string; content: string }) {
  const res = await fetch(`${API_BASE}/api/comments`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(data),
  });
  return res.json();
}
```

**地址切换**：需要指向其他后端时，在 `.env.local` 设置 `NEXT_PUBLIC_API_URL` 后重新构建上传 COS；未设置时回退到生产 API 地址。

### Dockerfile（多阶段构建）

```dockerfile
FROM node:22-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci --registry=https://registry.npmmirror.com
COPY tsconfig.json ./
COPY src/ src/
RUN npm run build

FROM node:22-alpine AS runtime
WORKDIR /app
ENV NODE_ENV=production
COPY package*.json ./
RUN npm ci --omit=dev --registry=https://registry.npmmirror.com
COPY --from=build /app/dist ./dist
EXPOSE 3001
CMD ["node", "dist/index.js"]
```

### docker-compose.yml

```yaml
services:
  api:
    build: .
    ports:
      - "127.0.0.1:3001:3001"   # 只绑定本机，外网统一走 Nginx
    volumes:
      - ./data:/app/data        # SQLite 文件持久化
    restart: always
    environment:
      - PORT=3001
      - NODE_ENV=production
      - ADMIN_KEY=${ADMIN_KEY:?请在 server/.env 中设置 ADMIN_KEY}
```

### Nginx 反代

仓库内的 `server/nginx.conf` 是最小可用配置（80 端口）。线上如果已经配置 HTTPS，请在服务器的 Nginx 站点中保留该反代逻辑：

```nginx
server {
    listen 80;
    server_name api.xolnxoln.cn;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

SSL 证书用腾讯云免费的一年期证书，或者 Let's Encrypt 自动续期。

### 部署命令

```bash
# ===== 以下 scp 在 Mac 本地执行 =====
ssh root@你的Lighthouse公网IP "mkdir -p /srv/blog-api/server"
scp -r server root@你的Lighthouse公网IP:/srv/blog-api/
scp server/.env root@你的Lighthouse公网IP:/srv/blog-api/server/.env

# ===== 以下命令在服务器上执行 =====
ssh root@你的Lighthouse公网IP
cd /srv/blog-api

# 首次从旧目录切换时，停止旧容器并迁移数据库
docker compose down 2>/dev/null || true
mkdir -p server/data
if [ -f data/blog.db ] && [ ! -f server/data/blog.db ]; then
  cp data/blog.db server/data/blog.db
fi

cd /srv/blog-api/server

# 启动（容器内自动 npm ci + tsc）
docker compose up -d --build

# 查看状态
docker compose ps
docker compose logs -f
```

### 什么是应用镜像

镜像就是服务器的"预装系统"。你买了 Lighthouse，腾讯云给你一台空的云电脑。

- **如果不选应用镜像**：你需要自己 SSH 进去，一步步装 Docker、配置防火墙、装 Node.js。大约 30 分钟。
- **选了 Docker 应用镜像**：腾讯云帮你预装好 Docker + Docker Compose。开机即用，省去 30 分钟的折腾。

类比：买一台新电脑。不选镜像 = 你收到一台只装了 Windows 的空电脑，软件自己装。选镜像 = 你收到一台已经装好了所有常用软件的电脑。

### 第二步：配置子域名

1. 进入 [DNSPod 控制台](https://console.dnspod.cn)，找到你的域名
2. 添加一条 DNS 记录：

| 字段 | 值 |
|------|-----|
| 主机记录 | `api` |
| 记录类型 | `A` |
| 记录值 | Lighthouse 的公网 IP（在控制台能看到） |

3. 保存后等几分钟生效

效果：`api.你的域名.com` → 指向你的 Lighthouse 服务器。

## 实际部署记录（2025-05-15）

### 做了什么

整个过程就是把后端架构方案中规划的东西在 Lighthouse 上跑起来。

**1. 环境准备**

服务器买的是腾讯云 Lighthouse + OpenCloudOS 8 + Docker 镜像。开机后发现只有 Docker，没有 git 和 Node.js。用 `yum install` 装上。

**2. 代码上传**

服务器在国内，GitHub 被墙，git clone 失败。改用 scp 从 Mac 直接上传 server 源码，Dockerfile 会在容器内完成编译。以后更新代码也推荐 scp 源码。

**3. 第一次构建失败——跨平台问题**

Docker 里运行 `better-sqlite3` 报错 `Exec format error`。原因是 `better-sqlite3` 是 C 编译的，Mac（ARM64）上编译的二进制在 Linux（x86_64）上跑不了。

Dockerfile 里加了 `apk add g++` 想在容器内重新编译，结果下载编译工具就要 10 分钟。

**4. 换 sql.js 解决**

`sql.js` 是纯 JavaScript 的 SQLite，不需要编译，不挑 CPU 架构。换掉后 Docker 构建 10 秒完成。个人博客这点访问量，性能和 better-sqlite3 没区别。

**5. 配 Nginx 让外网能访问**

服务器上装了 Nginx，配了个反向代理：80 端口的请求转发到容器里 3001 端口。DNS 已经配好 `api.xolnxoln.cn` → `193.112.220.113`。

**6. 验证**

```bash
curl http://api.xolnxoln.cn/api/health
# {"ok":true,"time":"..."}

curl -X POST http://api.xolnxoln.cn/api/comments \
  -H "Content-Type: application/json" \
  -d '{"slug":"test","section":"misc","author":"test","content":"测试"}'
# {"ok":true,"msg":"评论已提交"}
```

### 教训

- **能用纯 JS 就别用原生编译的库**。sql.js 比 better-sqlite3 部署省心太多
- **Docker 缓存不会自动更新代码**。修改源码后必须 `docker compose up -d --build`，`restart` 不会重新构建镜像
- **服务器国内访问 GitHub 可能被墙**，备好 scp 上传方案
- **CORS HTTP/HTTPS 混用**。前端 `https` 页面调 `http` API 会被浏览器拦截。本地开发用 `http`，生产环境前后端都上 `https`
- **数据库表修改不会自动生效**。`CREATE TABLE IF NOT EXISTS` 不会改已有表的默认值，INSERT 时显式写值为佳

## 安全注意事项

- **管理接口鉴权**：所有 `/api/admin/*` 请求必须携带 `x-admin-key`，密钥来自 `ADMIN_KEY` 环境变量；未配置或长度不足 12 位时服务拒绝启动
- **密钥管理**：`server/.env` 不入库，模板见 `server/.env.example`；换服务器时记得同步 `.env`
- **CORS**：API 只允许 `xolnxoln.cn` 和本地开发域名，防止其他网站恶意调用
- **限流**：当前为简易全局限流（每 IP 每秒最多 5 次），仅作为基础防护
- **输入校验**：所有用户输入做类型和长度限制；前端 React 默认转义输出
- **SQL 注入防护**：全部使用参数化查询，不拼接字符串
- **数据库落盘**：写盘采用“临时文件 + rename”原子替换，避免写一半损坏
- **端口暴露**：Docker 只绑定 `127.0.0.1:3001`，外网统一走 Nginx
- **HTTPS**：生产 API 使用 HTTPS；仓库内 nginx.conf 为 80 端口基础配置，证书配置在服务器侧
